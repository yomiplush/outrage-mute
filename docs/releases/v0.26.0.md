## Changes in v0.26.0

**No change to scoring, judgment, or any setting.** This release is about speed and about
being a well-behaved extension (fewer permissions, no page-readable assets).

### Faster: only changed posts are evaluated

X rewrites its DOM constantly (timers, video, virtualized lists). Until now every DOM
change rescanned the whole timeline and read the text of every post with `innerText`,
which forces a layout — the main reason scrolling felt heavy.

- A `MutationObserver` now maps changes to the affected `cellInnerDiv`s; **full scans
  happen only on startup and on settings changes**
- The queue is drained with a **~6 ms budget per turn**, so a busy timeline never becomes
  one long blocking task
- Post text is read with `textContent` (no forced layout) and results are cached per cell
  in a `WeakMap` keyed by a content hash — re-renders and scroll-backs are not re-scored
- The floating bar keeps a masked-cell **count** instead of querying `.jof-masked` on
  every mask, and follows cells that X removes
- `jof:masked` statistics are **batched for 2 s** instead of waking the service worker for
  every masked post (also fixes double counting on the userscript side)
- The own-handle lookup no longer re-queries the whole document for every post
- **Language packs are built lazily**: all 52 packs at startup cost ~40 ms; Japanese-only
  timelines now skip the other 51 and pay only for what they use

Measured on a synthetic 300–420 post timeline (headless Chrome, same machine, median of
3–4 runs):

| | before | after |
| --- | --- | --- |
| long tasks during initial load | 1 × ~110 ms | **0** |
| 5 s of unrelated DOM churn | 7,176 queries + 7,140 `innerText` reads, 53 ms script | **2 queries, 0 reads, 2 ms** |
| 6 s of appending + re-rendering posts | 9,012 queries, 8,776 `innerText` reads, 133 ms script | **393 queries, 0 reads, 44 ms** |
| messages to the service worker | one per masked post (57 / 6 s) | **3 per 2 s** |

### Chrome Web Store: minimal permissions, no page-readable assets

- **Removed `host_permissions`** — the extension makes no network requests, so host access
  is not needed; the content script `matches` on `x.com` / `twitter.com` is enough
- **Removed `web_accessible_resources`** — UI locale tables are now served by the service
  worker instead of exposing `_locales/*/messages.json` to the page (pages can no longer
  read any extension asset)
- Permissions are now exactly **`storage`**, with an explicit CSP
  (`script-src 'self'; object-src 'self'`) and no remote code
- `PRIVACY.md` rewritten for store review (what is stored, why each permission is needed,
  how to delete it, Limited Use) and `docs/store-listing.md` added with the listing copy,
  permission justifications, privacy answers and review notes
- New `npm run lint:store` checks the manifest, permissions, CSP, `__MSG_` length limits,
  icon dimensions, forbidden APIs, inline scripts and the ZIP contents before every release

## Main features (overall)
- Mute posts by outrage score (blur / fully hide · "Re-mute" after revealing)
- **Language mute (always fully hides the one language you chose)**
- Writing style/tone, self-deprecation, AI debate/tech, disasters, world affairs, NSFW, user dictionary (edited in a separate window), excluding your own posts, excluding replies
- Art focus mode (gentle / normal / strict) + avoiding long posts and replies, hiding notification/DM badges and the notifications tab
- **`Shift+1` shortcut on PC only**, 52 packs / 49 locales / script-based automatic detection
